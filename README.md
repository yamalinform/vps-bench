# vpsbench

Утилита для стандартизированного тестирования VPS: процессор, криптография, память,
диск, сеть, плюс паспорт железа и гипервизора.

Все тесты (fio, sysbench, iperf3 и др.) зафиксированы в едином Docker-образе, прибитом
по digest, поэтому результаты разных серверов можно корректно сравнивать между собой.

## Быстрый старт

```bash
curl -fsSL https://raw.githubusercontent.com/yamalinform/vps-bench/main/run.sh -o run.sh && bash run.sh
```

Скрипт спросит нужные параметры в терминале. Быстрый тест идет 5-10 минут (зависит
от процессора), полный примерно 40 минут.

⚠️ **Если запускаете по SSH, берите `--detach`.** Иначе обрыв связи убьёт замер
целиком, и сорок минут работы пропадут. С этим флагом прогон уходит в фон, а ход
пишется в `~/vpsbench-detached.log`:

```bash
bash run.sh --detach --yes --install-docker yes --depth full --vantage "my-vps-1"
```

## Как это работает

* **Docker как окружение.** Все утилиты запускаются в контейнере. Если Docker не
  установлен, скрипт предложит его поставить и удалит за собой после тестов
  (если Docker уже был, не тронет).
* **Убирает за собой при любом завершении**, где оболочка ещё жива: отказ, Ctrl-C,
  разрыв связи, ошибка посреди замера. Снимается ровно то, что было установлено,
  а не список имён наугад. При `kill -9` или потере питания обработчику неоткуда
  взяться, поэтому уборка переносится на следующий запуск: он опознает свой Docker
  и снимет его. Чужой Docker не трогается никогда.
* **Права.** Контейнер запускается с `--privileged` и `--network host`: это нужно
  для прямого доступа к диску и сети хоста, иначе замерялся бы контейнер, а не сервер.
  ⚠️ Изоляции при таких флагах нет. Контейнер здесь это способ доставки инструментов
  с правами root, а не песочница. Если такие права неприемлемы, инструмент вам
  не подходит, и честнее сказать это здесь, чем спрятать в мелком шрифте.
* **Приватность.** Результаты **никуда не отправляются**. Никакой телеметрии
  и аккаунтов, всё сохраняется только локально. Наружу скрипт ходит в три места,
  и список печатается на экране до старта: `ghcr.io` за образом, репозитории вашей
  же системы (только если Docker придётся ставить), точки замера скорости.

## Замер сети

Для честного замера скорости канала нужна вторая машина (например, ваш ноутбук или
другой сервер). На ней тоже понадобится `run.sh`:

```bash
# На второй машине:
curl -fsSL https://raw.githubusercontent.com/yamalinform/vps-bench/main/run.sh -o run.sh
bash run.sh --agent
```

Она поднимет приёмную сторону (три порта, ни одного пакета на машине) и будет держать
её, пока вы не нажмёте Ctrl-C. На основном сервере укажите IP второй машины, когда
скрипт спросит про сеть.

*Публичные точки (Cloudflare, зеркала Debian и Яндекса) меряются **всегда**, независимо
от того, есть ли у вас вторая машина, и идут отдельным разделом отчёта. Это замер пути
до чужого сервиса, а не вашего канала как такового, поэтому замер до второй машины
он не заменяет и с ним не смешивается.*

## Что на выходе

В папке `~/vpsbench-report-<метка>/`:
* `.md`: текстовый паспорт сервера, основной формат, по нему удобно делать `diff`;
* `.html`: тот же паспорт для чтения глазами (открывается в браузере без интернета);
* `.json`: данные для скриптов и построения дашбордов;
* `raw-run/`: исходные логи тестов, по ним отчёт можно пересобрать.

*Если у метрики разброс между прогонами превышает 20%, она помечается как «НЕНАДЁЖНО».
Метрика, которую снять не удалось, остаётся в отчёте строкой «не измерено» и не исчезает:
иначе два отчёта нельзя было бы сравнивать построчно.*

## Запуск без вопросов (для скриптов)

```bash
bash run.sh --yes --install-docker yes --depth quick --vantage "my-vps-1"
```

⚠️ `--yes` отвечает только на вопрос о начале замера. Установка Docker под него
намеренно не попадает, поэтому в скрипте её нужно разрешить отдельно флагом
`--install-docker yes`, иначе прогон остановится с сообщением, что без Docker
замер невозможен.

Основные флаги:
* `--depth quick|full`: глубина теста (быстрый / полный);
* `--vantage ИМЯ`: имя сервера в отчете;
* `--target МЕТКА:IP`: адрес второй машины с запущенным `--agent`;
* `--impact bench|observe`: максимальная нагрузка или щадящий режим (для рабочего сервера);
* `--no-network`: пропустить замер до второй машины (публичные точки при этом снимаются);
* `--install-docker yes|no`: ставить ли Docker автоматически;
* `--detach`: запустить отсоединённо и сразу вернуть управление;
* `--update yes|no` / `--reboot yes|no`: обновлять/перезагружать ли ОС (по умолчанию `no`).

Если терминала нет, а флаг не задан, берётся безопасный ответ, и скрипт говорит об этом
вслух. Систему без явного `--update yes` он не обновит, а машину без `--reboot yes`
не перезагрузит.

## Сравнение серверов

Отчёты сравниваются на вашей машине, а не на тестируемом сервере: после уборки на нём
остаётся только папка с результатами, кода там нет. Понадобится клон репозитория
и `python3`:

```bash
git clone https://github.com/yamalinform/vps-bench.git && cd vps-bench

# Сравнить два сервера (аргументы это каталоги raw-run из их отчётов):
python3 assemble.py --compare ~/vpsbench-report-A/raw-run ~/vpsbench-report-B/raw-run --out diff.md

# Собрать HTML-дашборд по папке с .json из разных отчётов:
python3 dashboard/build.py папка-с-json/ --out dashboard.html
```

Сравнение сначала проверяет, можно ли вообще сравнивать: совпадают ли версия инструмента,
версии измерителей, режим запуска и набор публичных точек. Различие, не превышающее
собственный разброс метрики, помечается как незначимое.

## Требования

* Linux x86_64 (дистрибутив не важен);
* Docker, либо `apt`, чтобы скрипт мог его поставить;
* root или `sudo`;
* ~1.5 ГБ свободного места на диске.
