# dashboard/ — визуальный вид отчёта vpsbench

> **Заведён:** 30.08.2026 по утверждённому владельцем дизайну (`../dashboard-design/`).
> Markdown остаётся **каноническим** форматом: по нему делают `diff` и `grep`,
> он версионируется. Дашборд — второй вид над теми же данными, для чтения глазами
> и для сравнения нескольких площадок сразу.

Этот README — **контракт**: что во что превращается, где проходит граница между
Python и браузером, и как это проверять. Написан для агента, который видит код впервые.

---

## 1. Сборка

Вход — JSON от `assemble.py --json` (`schema_version: "1"`). Только stdlib.
Запуск из корня `vps-bench/`:

```bash
python3 dashboard/build.py results/ --out reports/dashboard.html
```

`build.py` берёт **все** `.json` из папки и вшивает их в один файл. Сколько прогонов
в папке — столько площадок в дашборде. Выход — **один самодостаточный HTML**:
CSS и JS внутри, шрифты системные, **0 внешних ссылок**. Открывается двойным кликом
без интернета, шлётся одним файлом, кладётся в архив.

> На Windows вывод в консоль читается только с `PYTHONIOENCODING=utf-8` —
> иначе CP1251 покажет кракозябры (на сам файл это не влияет).

**Новый прогон появляется в дашборде после пересборки.** Иначе нельзя: страница,
открытая как `file://`, не может ни прочитать список файлов в папке, ни запросить
соседний JSON — это запрещено политикой браузера, а не недоработка. Плата за
«один файл, работает офлайн» — одна команда после каждого замера, которая и так
запускается рядом с `assemble.py`.

## 2. Устройство: build.py + template.html

| Файл | Роль |
|---|---|
| `template.html` | **Единственный источник разметки и вида**: палитра, типографика, каркас, клиентский рендерер. Правится руками при смене вида |
| `build.py` | Данные: читает JSON, строит view-model по реестру, вшивает её в шаблон |
| `verify.py` | Сверка с markdown — см. §5 |

Разметка перенесена из утверждённых мокапов `../dashboard-design/`. Мокапы после
переноса **заморожены** и живут как запись об утверждении; правки вида делаются
здесь, в `template.html`.

## 3. 🔑 Граница «Python ↔ браузер»

Это главное правило файла. Нарушить его — значит завести второй источник правды
и разойтись с markdown в числах.

**Python считает всё, что не зависит от выбора площадок:**
состав и порядок строк по `../registry.py`, форматирование чисел, разброс между
повторами, надёжность, причины отсутствия, факты о машине, защита процессора,
условия прогона, фризы, следы. Форматирование берётся **импортом из `../assemble.py`**
(`fmt`, `g`, `sep`, `spread_pct`) — не переписывается.

**Браузер считает только то, что зависит от выбора:**
шкалы полос (максимум по выбранным), разницу относительно опорной площадки,
значимость различия, пометки направления.

**Пороги передаются из Python** в `thresholds` (`SPREAD_OK`, `SPREAD_WARN`,
порог показа стрелки) и в JS не хардкодятся. В браузере остаётся три строки
арифметики, а границы и числа приходят из одного места.

## 4. Что показывают экраны

**Паспорт площадки** — утверждённый дизайн: визитка машины, сводка-плитки с кольцом
разброса, карточки (процессор, память, виртуализация, система, условия прогона),
защита процессора лентой, показатели полосами с насечкой размаха, сеть, фризы,
что не измерено, следы и воспроизведение. В шапке — выбор площадки и галочка
«в сравнение».

**Сравнение** — тот же дизайн, обобщённый на **2–6** площадок:

- **Разница считается относительно опорной площадки.** Опорная переключается кликом.
  Правило — то же, что в `assemble.py::cmp_row`: `100 × (v − v_опорной) / |v_опорной|`;
  разница **незначима**, если она меньше худшего разброса пары, и тогда полосы
  приглушаются, а стрелка не ставится. При двух площадках экран совпадает
  с утверждённым дизайном один в один — это его обобщение, а не новая механика.
- Полосы всех выбранных растут от общего нуля в общей шкале семейства.
  **Семейство = единица реестра:** длины сравнимы только внутри одной единицы.
- Выше шести площадок выводится предупреждение, но **ничего не скрывается**.
- Цвет — опознавательный знак площадки; при трёх и более на него не опираются,
  подпись стоит у каждой полосы.
- Раздел «Сеть» разниц не считает: у каждой площадки своя цель, это разные плечи.

## 4.1 🔒 Верность дизайну — что запрещено менять по своей инициативе

Вид утверждён владельцем. **Интерфейс, типы и размеры элементов, цвета, шрифты,
расстановка и логика полос — не предмет усмотрения исполнителя.** Взято из
`../dashboard-design/` дословно и проверяется машинно:

| Что | Откуда | Как проверено |
|---|---|---|
| Палитра (41 переменная, обе темы) | оба мокапа | посимвольное сличение значений |
| Сетки строк, высоты полос, кегли, ширины колонок | оба мокапа | сличение 18 сигнатур инлайн-стилей |
| Состав, порядок и подписи семейств шкал | `buildRows`/`mkRows` | зашито в `LAYOUT` (`build.py`) |
| Формулы шкалы, насечки, цветов, приглушения | `buildRows`/`mkRows` | перенесены построчно в `template.html` |

**Три правила, которые легко нарушить незаметно** — из-за них вид и «поехал» в первой
редакции 30.08.2026:

1. **Шкала семейства считается по верхней границе разброса** — `num × (1 + разброс/100)`,
   а не по медиане. По медиане насечка размаха вылезает за полосу и за пределы экрана.
2. **Цвет полосы и насечки зависит от разброса**, а не постоянный: полоса краснеет
   при разбросе выше 20 %, насечка — красная выше 20 %, янтарная выше 5 %. Это несущая
   часть смысла: нестабильное число видно, не читая процентов.
3. **Семейства заданы явно и не выводятся из единицы реестра.** Вывод «семейство =
   единица» даёт повторяющиеся заголовки шкалы вперемешку — в дизайне их нет.

**Отступления от мокапа — оба зафиксированы, других быть не должно:**

1. **Правка недосмотра.** В `band()` левый край насечки дополнительно поджимается,
   чтобы «левый край + минимальная ширина» не превышали 100 %. Формула дизайна
   зажимает только верх, и на реальных данных насечка у самого края полосы всё равно
   вылезала. Замысел (насечка внутри полосы) сохранён.
2. **Дополнение по указанию владельца 30.08.2026:** в карточке процессора добавлена
   строка «поколение: `<год> · <кодовое имя>`». В мокапе её нет — это не дрейф вида,
   а поручение. Краткая форма выбрана, чтобы карточка осталась компактной: полная
   формулировка с оговоркой живёт в подсказке, в таблице фактов и в markdown.

Проверка геометрии, которую стоит повторять после любой правки вида: открыть отчёт
и убедиться, что ни один вложенный элемент полосы не выходит за свою дорожку
(команда — в §5).

## 5. Проверки

```bash
python3 dashboard/verify.py results/ reports/
```

Проверяет два обязательства:

1. **Все позиции реестра на месте** у каждой площадки — включая неснятые.
   Если на одной паспорт строку показывает, а на другой нет, сопоставление
   построчно разрушено, и это уже не косметика.
2. **Числа совпадают с markdown дословно.** Оба вида строятся из одного JSON,
   но разными путями; расхождение заметил бы не тот, кто правил код, а тот,
   кто по этим числам покупает VPS.

Флаг `--deltas` печатает эталон разниц, посчитанный правилом `assemble.py`.
С ним сверяется то, что считает браузер: снять в консоли страницы те же разницы
и сравнить поэлементно. Сверка 30.08.2026 на паре двух площадок — **28 из 28
совпали**, включая признак значимости и направление (у метрик с направлением
«меньше — лучше» стрелка обратная).

Проверки вида, которых `verify.py` не делает:

```bash
grep -c http reports/dashboard.html   # должно быть 0
```

Геометрия полос — в консоли открытого отчёта; должно быть `0`:

```javascript
[...document.querySelectorAll('.rowh')].flatMap(r=>[...r.querySelectorAll('div[style*="position:relative"]')].flatMap(t=>{const b=t.getBoundingClientRect();return [...t.children].filter(c=>{const k=c.getBoundingClientRect();return k.right>b.right+.5||k.left<b.left-.5})})).length
```

Прогонять на **каждом** паспорте, в **обеих** темах и на экране сравнения:
вылет зависит от данных конкретной площадки, а не от вёрстки.

## 6. Как расширять

- **Новый показатель** — только в `../registry.py`, в конец своей группы.
  Дашборд подхватит его сам: и строку, и полосу, и позицию в сравнении.
  Ничего в `dashboard/` править не нужно.
- **Новая единица измерения** — добавить человеческое имя семейства в `FAMILY`
  (`build.py`), иначе разделитель шкалы напишет саму единицу. Не ошибка, но грубо.
- **Правка вида** — `template.html`. Числа при этом не трогать: они приходят готовыми.
- **Правка формата числа** — только в `../assemble.py`. Изменится сразу в обоих видах,
  и `verify.py` подтвердит, что они не разошлись.

## 7. Известные ограничения

- **Список площадок фиксируется при сборке** (см. §1) — это цена одного офлайн-файла.
- **Выбор площадок не сохраняется** между открытиями: при каждом открытии выбраны
  первые две по алфавиту. Осознанно — состояние в URL или `localStorage`
  усложняет файл ради удобства, о котором никто не просил.
- **Сравнение выше шести площадок** предупреждает, но не запрещает: полосы в строке
  становятся нечитаемыми раньше, чем данные перестают быть верными.
- **Раздел «Сеть» в сравнении** сопоставляет разные плечи (у каждой площадки своя
  цель) и потому не считает разниц. Это свойство замера, а не недоделка вида.
